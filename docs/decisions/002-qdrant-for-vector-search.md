# ADR 002: Use Qdrant for Vector Search

## Status

Accepted

## Context

The application requires semantic similarity search over embedded documents.

A traditional relational database is not the primary storage mechanism for vector similarity search in this architecture.

## Decision

Use Qdrant as the vector database.

Embeddings generated by the configured embedding model are stored in Qdrant and retrieved through similarity search.

## Consequences

Vector search is separated from relational application data.

The embedding provider and Qdrant configuration can evolve independently from SQLite.

Documents stored in Qdrant should contain enough metadata to associate retrieved vectors with the corresponding application records when required.
